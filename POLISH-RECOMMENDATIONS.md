# GVDG Portal — Gold-Standard Improvement Catalog

> Prioritized functional + visual recommendations for **already-shipped** features, to take the
> Greenville Disc Golf Club portal to a gold-standard, club-member-friendly bar. Produced by a
> multi-agent audit (10 feature areas, adversarially synthesized) on 2026-06-24.
> **Not covered here:** the new `score.html` live-scoring flow and the tee-sign-capture track (handled separately).

**89 recommendations** — 40 high, 39 medium, 10 low · 62 functional / 27 visual.

## Top themes

- Honest async states (loading / error+retry / empty vs failed) are missing almost everywhere — fetchJson/loaders swallow errors to null across auth-dashboard, board, events-hub, fundraisers-meetings, leagues, and crotts-ai, so a network/CDN/GitHub-raw failure renders the same cheerful 'no data yet' as a genuinely empty state. This silently erodes trust on the club's most-viewed surfaces and is the single most repeated defect.
- 'Backend already computes/supports it, the UI just throws it away.' Repeated capability-vs-surface gaps: standings podiums/best_place (leagues), DO snapshot holes[]/meta.updatedAt thru-count + freshness (events-hub), cancelled bucket from bucketEvents (events-hub), updateLeague PUT route with no admin UI (leagues), registerForEvent ON CONFLICT upsert enabling edit-without-withdraw (registration), meeting attendees JSON (fundraisers-meetings), Ryder Cup W/L/T + Format/Course columns the parser discards. Many of these are S/M effort with zero new backend work.
- Freshness, recency and 'is this live?' signals — relative <time> timestamps, 'updated Ns ago', unread/new-post badges, live thru-counts, auto-promote scheduled->live, last-synced stamps. The portal's whole reason to be revisited (board, dashboard, live leaderboard, Ryder Cup, fundraiser momentum) hinges on these and they're largely absent.
- Mobile-first PWA + on-course reality: no web app manifest / apple-touch-icon (not installable), no service worker (every dynamic surface hard-fails with no signal deep in the woods), dark-mode flash on every page nav, dense admin score/roster tables that only horizontal-scroll and lose the player-name column. The primary device and environment (a phone in a wooded park on flaky data) is under-served.
- Action-confirmation + double-submit safety across all interactive surfaces: alert()-based errors and silent re-renders instead of inline confirmation/receipts (registration, admin's single offscreen #adminMsg bar), un-disabled Post/Pay/create buttons that double-fire, and destructive actions (clear live scores, finalize, cascade-delete a thread) behind a bare native confirm() with no consequence echo.
- Accessibility floor is below WCAG baseline portal-wide: missing focus-visible rings (members page strips them with outline:none), divs-with-onclick accordions that keyboard users can't open, no aria-live on any dynamic/live region (leaderboard, board, admin feedback, fundraiser progressbar), no skip link on 4 of 6 pages, no aria-current nav, and animations ignoring prefers-reduced-motion on 5 of 6 pages.
- Personalization & social engagement is thin: Crotts can't greet by name or answer 'what am I registered for' despite the token being right there; the league standings don't highlight 'You'; the board has no avatars/reactions/mentions; events have no roster/headcount or 'add to calendar'/native share. The mechanics that make a club app sticky vs a brochure are mostly unbuilt.
- Design-system fragmentation: brand tokens and dark-mode overrides are copy-pasted into 6 HTML files (already drifting), the directory inlines a 262KB roster, and component styles are borrowed across contexts (rounds list reuses player-roster CSS). No single source of truth for theme, components, or the member roster.

## Recommended roadmap (most member value, fastest)

0. Phase 0 — Shared foundation (do first; everything else rides on it). Extract tokens.css + base.css design system; ship the web app manifest + apple-touch-icon + service worker (offline shell + stale-while-revalidate for Worker JSON/Sheet CSV, and move the 262KB inlined roster to a cached JSON); move theme-init to a pre-paint inline <head> script on all 6 pages. Result: installable, offline-tolerant, flash-free club app and one place to re-skin. (global-pwa)

1. Phase 1 — Honesty & trust quick wins (highest value-per-hour, mostly S effort). Fix the swallow-to-null loaders so error+retry is distinct from empty across auth-dashboard, board, events-hub, fundraisers-meetings, leagues, Crotts; render board timestamps as relative <time>; render the cancelled-events bucket; surface the league podiums/best-finish/points-legend the worker already computes; add the running fee total + an itemized paid receipt and replace alert()s in registration. These remove the most damaging 'site looks broken / I don't trust the number' moments at near-zero cost. (board, events-hub, leagues, registration-payments, auth-dashboard, fundraisers-meetings)

2. Phase 2 — Interaction safety & feedback (prevents real day-of-tournament mistakes). Replace admin's single offscreen #adminMsg with fixed auto-dismissing toasts; add the shared submit-guard to every create/save/pay/post button (kills double-events, double-posts, double-pays); add PayPal in-flight 'Confirming payment…' state; upgrade the two irreversible admin actions (clear scores, finalize) and the cascade-delete-thread warning to a consequence-echoing confirm. (admin-portal, registration-payments, board)

3. Phase 3 — Accessibility sweep (one coordinated pass on the now-shared CSS/markup). Global focus-visible ring + skip link on all pages, role=status/aria-live on every async & live region (leaderboard, board, admin toasts, fundraiser progressbar, Crotts log), aria-current nav, keyboard-operable accordions, prefers-reduced-motion in the shared sheet, native Web Share + 'Add to calendar' (which also need the aria/semantic <time> groundwork). (global-pwa, events-hub, fundraisers-meetings, ryder-cup, crotts-ai)

4. Phase 4 — Freshness & live engagement (the 'reason to revisit' layer). Unread/new-posts badge + collapsible reply counts on the board; live thru-count + 'updated Ns ago' + auto-promote scheduled->live on the events leaderboard with the in-place row-flash (the dead .lb-upd CSS) and visibility-pause; Ryder Cup week selector + derived winner coloring + per-player W/L/T + consolidated refresh; persistent profile-completion nudge with completion meter; last-synced stamp + skeletons + trend arrows on the dashboard tiles. (board, events-hub, ryder-cup, auth-dashboard)

5. Phase 5 — Personalization, social & richer function (the stickiness layer). Crotts member-aware (forward the token, greet by name, answer 'what am I registered for', plus quick-action chips, streaming, persisted conversation); highlight + pin the member's own league row; board avatars/reactions/mentions; passkey manager + 'keep me signed in'; live event roster/headcount; let members edit division/add-ons without withdraw; admin Overview dashboard + grouped/searchable events + roster bulk actions. (crotts-ai, leagues, board, auth-dashboard, registration-payments, admin-portal)

6. Phase 6 — Governance, history depth & long-tail polish. Unify meetings onto the D1 path (retire hardcoded accordions) with first-class action items (assignee/due/status carried forward); expandable per-round event history; pagination/'load more' for board and past-events; admin edit-league lifecycle; fundraiser deadline/momentum + goal-reached celebration; SEO/OG meta. (fundraisers-meetings, auth-dashboard, board, events-hub, leagues, global-pwa)

## Cross-cutting investments (build once, reused everywhere)

- Shared design-system stylesheet (tokens.css + base.css): extract the duplicated :root brand palette and the 24+ [data-theme=dark] override blocks copy-pasted across index/events/blog/ryder-cup/members/admin into one cached source of truth (they already drift, e.g. ad-hoc var(--card-bg,#2a2a3e) only in index). One edit re-skins the whole site and GitHub Pages caches it across navigations. (global-pwa)
- PWA shell: web app manifest + apple-touch-icon (installable club app) and a service worker (cache-first shell + stale-while-revalidate for Worker JSON and the published-Sheet CSV) so events, standings, and roster survive a dead-cell-zone deep in the woods — the defining 'club app vs website' capability, paired with moving the manifest-adjacent roster fetch (currently 262KB inlined in gvdg-members.html L1555) to a cacheable JSON file. (global-pwa)
- Pre-paint theme-init: a single inline <head> script (shared snippet) on all 6 pages to read localStorage theme and set data-theme before first paint, killing the white->dark flash on every navigation. (global-pwa)
- Accessibility baseline as one sweep: global *:focus-visible focus ring (and removing outline:none on members inputs), skip link on all 6 pages, role=status/aria-live=polite + aria-busy on every async/loading/error/live container (leaderboard, board, admin feedback toasts, fundraiser progressbar, Crotts message log), aria-current=page nav wayfinding, real <button>+aria-expanded accordions, and prefers-reduced-motion lifted into the shared stylesheet (currently only index.html honors it). (global-pwa + per-area)
- A reusable async-state helper/pattern: distinguish loading (skeleton) vs error+retry vs genuinely-empty, applied to the loaders that currently catch-to-null/empty and render a false 'nothing here' — fetchJson (auth-dashboard L945), loadBoard (board L1176), loadFundraisers / loadMeetings (fundraisers-meetings), renderLeague empty path, and Crotts. (auth-dashboard, board, events-hub, leagues, fundraisers-meetings, crotts-ai)
- A shared 'submit guard' helper that disables a button, swaps label to a spinner/'Saving…', and restores in a finally — applied to every create/save/pay/post/assign action that is currently freely double-clickable (admin's 7+ unguarded handlers L582-1161, board Post L1218, registration Pay/Register, registerCard). (admin-portal, board, registration-payments)
- Unified avatar/identity component (initials-in-a-circle fallback already exists as .member-avatar in the directory L220) reused across dashboard header, board posts, league 'You' row, and roster, plus 'You'/admin badges — one identity primitive instead of per-surface name-only rows. (auth-dashboard, board, leagues)
- Standardized live/freshness primitives: an 'updated Ns ago' clock from meta.updatedAt, a consolidated single-refresh() function (events-hub and ryder-cup both copy-paste their whole fetch+render body into the interval and never clearInterval), and a document.visibilitychange pause-on-hidden + refresh-on-show guard so backgrounded tabs stop draining phone battery during a long round — applied to events-hub live leaderboard and ryder-cup. (events-hub, ryder-cup)
- A vetted markdown allowlist renderer already living in gvdg-members.html (mdRender/mdInline L1009-1035, createElement/textContent + http(s)-link allowlist) should be the shared safe-render utility reused by Crotts (crotts.js bubble L54-59) and the meeting minutes renderer — satisfies the no-innerHTML XSS rule in one place. (crotts-ai, fundraisers-meetings)
- A themed confirmation-modal component (consequence-echoing, with typed/second-step confirm for the two irreversible paths: clear-live-scores admin.html L860 and finalize L943, plus the cascade-delete-thread warning board L1198) to replace scattered native confirm() calls site-wide. (admin-portal, board)
